# Секция 9: Diagnosis Builder + API

**Дата:** 2026-04-07
**Статус:** утверждено Петром

---

## Назначение

Diagnosis Builder — "последняя миля" движка. Получает от Rule Engine список сработавших правил (с уверенностью и фактами) и превращает сухой технический результат в полезный, понятный отчёт для пользователя. От качества этого шага зависит, заплатит ли пользователь.

---

## Полный диагностический отчёт (7 блоков)

Движок ВСЕГДА генерирует все 7 блоков. Слой отображения решает что показать:
- Приложение → блоки 1-2 + топ-3 из блока 3
- Дашборд → всё
- PDF → блоки 1-3-4-5-7

---

### Блок 1: "Безопасно ли ехать?"

Самое важное — первое что видит пользователь. Три варианта:

**БЕЗОПАСНО (зелёный):** нет проблем с severity=danger или critical. "Всё в порядке, спокойно езди."

**ОСТОРОЖНО (жёлтый):** есть warning-уровень, ничего критичного. "Можешь ехать, но запишись на диагностику в ближайшую неделю."

**НЕ ЕХАТЬ (красный):** есть danger-уровень — перегрев > 105°C, LTFT > 37%, DTC с can_drive=no_stop, напряжение < 11V. "Останови машину. Вызови эвакуатор."

Определяется по ХУДШЕМУ факту: если хотя бы один = danger → всё красное.

---

### Блок 2: Health Score (общая оценка здоровья)

Число 0-100 по каждой системе + общее:
- Подвеска — из вибрации (T2)
- Двигатель — из LTFT/STFT, coolant, RPM (T1)
- Электрика — из voltage (T1)
- Аудио — из звуковых аномалий (T3)
- Общее — взвешенное среднее

Рядом с каждой оценкой — тренд: ↑ улучшается, → стабильно, ↓ ухудшается (из CUSUM).

Уверенность: "На основе 847 замеров за 14 дней" (высокая) или "На основе 23 замеров за 2 дня, точность ограничена" (низкая). Если baseline < 30 замеров — "Проедь ещё 5 поездок для точной оценки."

---

### Блок 3: Список диагнозов

Каждый диагноз содержит:

**Заголовок + статус:** "Износ подвески — ВЕРОЯТНО (78%)"

**Человеческое объяснение (из KB situations → quickAnswer):** "Стуки в подвеске чаще всего — стойки стабилизатора (расходник, 2-4K руб.) или опорные подшипники."

**На чём основан вывод (из фактов):** "Вибрация по вертикальной оси в 2.3 раза выше нормы для вашей машины на трассе. Проблема повторяется 5 поездок подряд."

**Маршрутная карта ремонта — от бесплатного к дорогому (из KB + YouTube тесты):**
1. Визуальный осмотр: проверить пыльники, подтёки амортизаторов — бесплатно
2. Стойки стабилизатора — 2000-4000 руб. (расходник, менять первым)
3. Опорные подшипники — 3000-6000 руб.
4. Амортизаторы — 8000-20000 руб. за пару (менять только парой!)

**Типичные ошибки (из KB → commonMistakes):** "Не меняйте амортизаторы, не проверив стойки стабилизатора — в 60% случаев проблема в них."

**Можно ли ехать:** "Да, но избегайте плохих дорог и высокой скорости."

**Ориентировочная стоимость:** "3000-20000 руб. в зависимости от причины"

---

### Блок 4: Калькулятор потерь (для топливных проблем)

Только когда FuelTrim Analyzer нашёл проблему.

Формула: перерасход = LTFT% × базовый_расход × цена_литра × месячный_пробег / 100

Пример: "LTFT +15%, расход 10 л/100км, АИ-95 = 55 руб/л, 1500 км/мес → вы теряете ~1240 руб. в месяц. За год — 14 880 руб. Ремонт окупится за 2 месяца."

Параметры:
- LTFT% — из FuelTrim Analyzer
- Базовый расход — из vehicles-ru.json (specs модели) или ввод пользователя
- Цена топлива — средняя по региону или ввод
- Месячный пробег — из Vehicle Profile (mileage_km / количество месяцев)

---

### Блок 5: Отзывные кампании

**УЖЕ ПОЛНОСТЬЮ РЕАЛИЗОВАНО** в основном проекте (D:\transfer4):

Существующая система (`frontend/screens/recalls.js`, 1472 строки):
- 9-уровневая параллельная проверка через Promise.allSettled()
- Источники: локальная БД (298 кампаний) + Gazbuka.ru (Росстандарт по VIN) + NHTSA VIN + NHTSA Vehicle + Porsche API + Geely Perxis + Toyota/Lexus/GAC Tradedealer + Transport Canada + easy.gost.ru
- Flask backend с CORS-прокси для всех API (web_control.py, строки 5106-5485)
- VIN-декодер интегрирован (630 WMI кодов, 46 мульти-бренд)
- Кэширование 24 часа в localStorage
- i18n: русский, английский, китайский, арабский, испанский
- Оффлайн-режим через локальную БД

**Задача для движка:** НЕ реализовывать заново, а ИНТЕГРИРОВАТЬ существующую систему. При формировании диагностического отчёта:
1. Взять brand + model + year из Vehicle Profile
2. Вызвать существующую recalls-проверку
3. Если есть совпадения — включить в отчёт как отдельный блок
4. Приоритет: severity=critical отзывные → показывать в блоке 1 ("Безопасно ли ехать?")

---

### Блок 6: Escalation (нарастание серьёзности)

Для каждого диагноза — история эскалации из diagnostic_persistence:
- "Обнаружено 12 дней назад. Тренд: ухудшение. Текущий уровень: ПРОБЛЕМА."
- Если отклонялось ранее: "Вы отклонили этот диагноз 7 дней назад, но проблема усилилась."

---

### Блок 7: Рекомендации по следующим шагам

Конкретные действия, приоритизированные:
- "Запишитесь на диагностику ходовой в ближайший сервис"
- "Проведите тест крышки маслозаливной (инструкция в приложении)" — для LTFT проблем
- "Проверьте уровень тормозной жидкости"
- "Обновите приложение для более точной диагностики" (если rule_version устарел)
- "Обратитесь к дилеру по отзывной кампании [название] — ремонт бесплатный"

## API контракт

### POST /api/v2/diagnose/ — основной endpoint

**Запрос от приложения:**
- client_hash — идентификатор клиента
- vehicle_profile — при первом запросе или изменении (VIN, brand, model, generation, modifications)
- data — пакет данных: OBD пакеты + accel_windows + audio_windows за период
- dtc_codes — список активных кодов ошибок
- tier — T1/T2/T3
- ambient_temp — температура за бортом (если доступна)

**Ответ сервера:**
- can_drive: safe / caution / stop — "безопасно ли ехать"
- health_scores: {overall, suspension, engine, electrical, audio} — каждый 0-100
- health_trends: для каждой системы ↑/→/↓
- confidence: 0.0-1.0 + количество замеров + сколько нужно для точности
- diagnoses: список диагнозов — каждый содержит:
  - rule_name, display, status (likely/possible/unlikely/clear)
  - confidence: 0-100
  - explanation: человеческое объяснение
  - evidence: на чём основан вывод (список фактов)
  - repair_roadmap: маршрутная карта [{step, description, cost, is_free}]
  - common_mistakes: чего НЕ делать
  - can_drive: для этого конкретного диагноза
  - price_range: ориентировочная стоимость
  - situation_id: ссылка на KB
- fuel_loss: {monthly_rub, yearly_rub, ltft_pct, formula_details} — потери (если LTFT проблема)
- recalls: список совпавших отзывных кампаний
- escalations: диагнозы с историей {first_seen, days_active, trend, level, was_dismissed}
- next_steps: приоритизированные рекомендации
- rule_version: версия правил на сервере
- baseline_status: {total_samples, samples_needed, ready: bool}

### POST /api/v2/feedback/ — обратная связь

**Запрос:**
- client_hash
- rule_name — какое правило оценивает
- diagnosis_time — когда был поставлен диагноз
- action: confirmed / dismissed / resolved
- comment — опционально

**Ответ:** {success: true}

### GET /api/v2/history/ — история для графиков

**Параметры:** client_hash, period (7d/30d/90d)

**Ответ:** массив anomaly_scores + diagnoses за период. Для графиков трендов в дашборде.

## Форматы вывода

### Приложение (основной)
JSON → нативный UI. Показывает:
- Светофор (безопасно/осторожно/не ехать)
- Health Score (0-100) с трендом
- Топ-3 диагноза с кратким объяснением
- Кнопки "подтверждаю" / "не так" для feedback

### Дашборд (llcar.ru/v2/)
Тот же JSON → React компоненты. Показывает ВСЁ:
- Полные графики трендов
- Все диагнозы с маршрутными картами
- Корреляции accel↔audio
- Калькулятор потерь
- История эскалации

### PDF для СТО
Генерируется на сервере по запросу. Формальный отчёт:
- VIN, пробег, дата обследования
- Health Score по системам
- Список диагнозов с фактами
- Рекомендации
- Цель: "документ для контроля СТО" (CustDev инсайт #3: недоверие к СТО, "260 000 руб. впустую")
