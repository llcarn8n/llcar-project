# Секция 2: Vehicle Profile

**Дата:** 2026-04-07
**Статус:** утверждено Петром

---

## Назначение

Vehicle Profile — обязательный компонент, без которого невозможна корректная диагностика. Определяет:
- Какую Knowledge Base загружать (4-level: brand → model → generation)
- Какие коррекции применять к LTFT/STFT (ГБО, Евро-2, платформа, марка)
- Какие recalls проверять
- К какой группе относить для ML (per platform/brand)

---

## Поля профиля

### Идентификация
- **VIN** — читается автоматически через OBD Mode 09 PID 02. Приложение v1.04 уже умеет, но есть баги (хардкод CAN ID, iOS парсер).
- **Brand** — определяется автоматически из WMI (первые 3 символа VIN). 630 WMI кодов в базе.
- **Year** — определяется автоматически из 10-го символа VIN. 30 кодов (2010-2039).
- **Model** — автоопределение: VIN → brand + year → фильтр vehicles-ru.json по годам выпуска (ys <= year <= ye) → короткий список 2-5 вариантов → пользователь тапает один раз. Исследование по полной VDS-декодировке ведётся (agent-vin-decode).
- **Generation** — определяется автоматически если у модели одно поколение на этот год. Если несколько — пользователь выбирает из 2-3 вариантов.
- **Engine code** — опционально, для точной диагностики. Может определяться через Calibration ID (Mode 09 PID 04).
- **Engine type** — ice/phev/bev. Может определяться через Fuel Type PID 0x51 (Li Auto возвращает "Hybrid Gasoline").

### Для калибровки движка
- **Mileage (пробег)** — обновляется из OBD PID 01A6 каждую поездку. Влияет на нормы (машина с 200K км имеет другие пороги).
- **Platform** — lookup в platform-sharing.json по brand+model. 32 платформы, 115 моделей. Используется для: калибровки LTFT (GM-платформы = +-10%), fallback при малом покрытии (VW/Skoda/Audi = одна платформа MQB).

### Модификации (критично для LTFT)
- **ГБО (LPG)** — пользователь отвечает при онбординге. Расширяет допуск LTFT до +-15-20%.
- **Евро-2 / удалён катализатор** — пользователь отвечает. Сдвигает "ноль" LTFT на -5...-10%. Без этого LLCAR даёт ложные тревоги.
- **Чип-тюнинг** — пользователь отвечает. Может определяться по Calibration ID (изменённая прошивка).

## Вычисляемые коэффициенты

### LTFT Base Offset (сдвиг нуля)
- Евро-2/удалён кат → сдвиг -7.5% (диапазон -5...-10%)
- Без модификаций → 0%

### LTFT Tolerance Multiplier (множитель допуска)
- ГБО → x1.5 (расширяет норму)
- GM-платформы → x1.3 (допуск +-10%)
- Японские марки (Toyota, Honda, Mazda, Subaru, Nissan, Mitsubishi) → x0.7 (уже +-7%)
- Без модификаций → x1.0

### KB Resolution Path (путь поиска в Knowledge Base)
Порядок: generation → model → brand → universal (most specific first).
Пример для BMW X5 E53:
1. `generation/bmw/x5/e53` (если есть)
2. `model/bmw/x5`
3. `brand/bmw`
4. `universal`

## VIN Decoding (автоматическая идентификация)

### Что уже работает в приложении v1.04
- Mode 09 PID 02 — чтение VIN через OBD (AndroidBluetoothOBD2Service.cs, lines 1582-2214)
- Автоматическое чтение при подключении, 2 retry, 3 секунды timeout
- VIN хранится в SettingsData.Vin, используется для ClientHash

### Баги в текущей реализации
1. ParseVinFromResponse() хардкодит CAN IDs (7E8, 7E0, 7E1, 7E9) — пропускает 7EA-7EF (Li Auto ECU)
2. iOS VIN парсер — простой string search для "4902" без proper multi-frame handling
3. Нет проверки поддержки Mode 09 (0900) перед попыткой — тратит 6 секунд на неподдерживающих авто

### Алгоритм онбординга
1. Подключение к ELM327 → автоматическое чтение VIN
2. WMI (1-3 символы) → brand + country (630 кодов)
3. Символ 10 → year
4. Фильтр vehicles-ru.json: модели этого бренда с ys <= year <= ye → короткий список
5. Если одна модель — автоматически. Если 2-5 — пользователь тапает один раз.
6. Поколение — аналогично по годам. Если одно — автоматически.
7. Fuel Type PID 0x51 → ice/phev/bev (автоматически)
8. Вопросы: "ГБО?", "Удалён кат / Евро-2?", "Чип-тюнинг?"

### Покрытие
- ~80% китайских авто (2018+) поддерживают Mode 09 (VIN через OBD)
- 100% авто с OBD-II поддерживают Mode 01 (базовые PID'ы)
- 15% дешёвых клонов ELM327 теряют кадры в multi-frame — retry уже реализован
