# 23. Специфичность ситуаций по уровням иерархии

**Дата:** 2026-04-07
**Вопрос:** Ситуации общие для марки или специфичны для поколения?

---

## TL;DR — Главный вывод

**Ситуации НЕ специфичны для поколения.** 4-уровневая иерархия (universal → brand → model → generation) — это фикция. Реально существуют только **2 слоя с уникальным контентом:**

1. **Universal** (764 шт) — общие для всех марок
2. **Brand** (доп. ~200-800 шт) — специфичные для бренда, из которых ~95% — это `manual_warning` (выдержки из сервисных мануалов)

Уровни model и generation — это просто **фильтрованные подмножества** brand-уровня. Контент копируется 1:1 без адаптации.

## 6. Вывод: есть ли смысл в 4-уровневой иерархии?

### Нет. Иерархия избыточна.

**Реальная структура данных:**

```
Universal (764) — общие диагностические ситуации
  ↓ копируются 1:1 (с OCR артефактами) в каждый бренд
Brand (+manual_warnings) — выдержки из мануалов + ~30 уникальных ситуаций
  ↓ фильтруются по полю "models" без изменения контента
Model (подмножество Brand) — 0 уникального контента
  ↓ добавляются manual_warning из мануала конкретного поколения
Generation (model + manual_warnings поколения) — 0 адаптации диагностики
```

### Что нужно изменить

1. **Model и Generation файлы можно не хранить** — они вычислимы из Brand-файла по полю `models`
2. **manual_warning записи** нужно отделить от диагностических ситуаций — это разные сущности
3. **Реальная адаптация под поколение отсутствует:**
   - Нет разных цен для E53 (2000-2006) vs F15 (2013-2018)
   - Нет специфичных причин для конкретного двигателя/КПП
   - Нет разных urgency в зависимости от возраста авто
4. **Дедупликация:** 405,751 модельных записей = ~836 копий ~485 записей = реально ~600-1200 уникальных записей на бренд

### Рекомендация

Вместо 4 уровней файлов использовать:

```
situations-universal.json (764)    — база
brands/{brand}/situations.json     — бренд-специфика + фильтр по models
brands/{brand}/manual-warnings/    — отдельно выдержки из мануалов
```

Для адаптации под поколение нужен **новый подход**: generation-specific overlays с реальными данными (цены, двигатели, типичные проблемы конкретного мотора), а не копирование одного текста.
